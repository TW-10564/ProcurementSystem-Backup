## What is DONE

### Phase 1 — portability fixes
- **`verify/mismatch.py`** — removed `func.julianday()` (SQLite-only; would
  have raised `UndefinedFunction` in production at a month boundary). It sat
  on a *fallback* branch with no test coverage, so it passed CI forever.
  Added the missing test.
- **NULL-ordering pinned** at 8 sites with `.nulls_first()` / `.nulls_last()`.
  SQLite sorts NULLs first on ASC, Postgres last — on "last row wins" loops
  that silently inverts which row wins. Highest impact was
  `forecast_views._stock_by_item`, which feeds **order quantities**.
- **`db.py`** — explicit Postgres pool (10+20, `pool_pre_ping`); the default
  5+10 would exhaust given report endpoints hold sessions for minutes.
- *Verified:* `/reports/mismatch` and `/forecasts/order-suggestions` output
  **byte-identical** before and after.

  previously returned `"skipped"` and let the rebuild proceed to `drop_all`

## Gotchas worth remembering

- **A failed backup aborts the rebuild.** Deliberate. If rebuilds start
  failing, check `pg_dump` and disk space first.
- **Code changes need a container restart.** The scheduler holds imported
  modules in memory — this bit us today, when a 13:00 auto-rebuild recreated
  a bug that was already fixed on disk.
- **One uvicorn worker.** Two would run two schedulers and could drop the
  database concurrently. Do not add `--workers`.
- **Rotating `ONEFCST_API_KEY` needs an image rebuild** — `VITE_API_KEY` is
  compiled into the JS bundle.
- **Use `npm run build`, not `vite build`, to check the frontend.**
  `tsc --noEmit -p tsconfig.json` checks *nothing* here (it is a solution
  file with references only) — that masked three real type errors all day.
- **String sort order differs** between SQLite and Postgres (byte order vs
  locale). Affects `/items` display order only, not correctness.
